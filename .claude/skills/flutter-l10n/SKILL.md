# Flutter localization: EN template, PT and ES translations

## When to use
Any time a widget needs text. The only literals allowed in widgets are the
language names in Settings (English, Português, Español are proper nouns).

## Inputs
- The English copy, and the Portuguese and Spanish translations.
- Placeholders, if any, with their Dart types (`int`, `String`).

## Steps
1. Add the key to `app/lib/l10n/app_en.arb` in camelCase. With placeholders,
   add the metadata entry right after it:
   ```json
   "hintsLeft": "{count, plural, =0{No hints left} =1{1 hint left} other{{count} hints left}}",
   "@hintsLeft": { "placeholders": { "count": {"type": "int"} } }
   ```
2. Add the same key with the translation to `app_pt.arb` and `app_es.arb`.
   Translations do not repeat the `@` metadata.
3. Run `flutter pub get` inside `app/` — it regenerates
   `lib/l10n/app_localizations*.dart` (git-ignored; `generate: true` in
   pubspec.yaml).
4. Use it: `AppLocalizations.of(context).hintsLeft(count)`. The getter is
   non-nullable (`nullable-getter: false` in `l10n.yaml`).
5. Widget test: pump with
   `localizationsDelegates: AppLocalizations.localizationsDelegates,
   supportedLocales: AppLocalizations.supportedLocales` and assert the
   English text; the test locale is en-US.

## Verify
- `flutter analyze` in `app/`: a key missing from the template is a compile
  error at the call site; a key missing from a translation is a generation
  warning naming the file.
- `flutter test` in `app/`.

## Pitfalls
- The generated files are outside git. A fresh clone shows red imports until
  `flutter pub get` runs.
- `dart format lib test tool`, never `dart format .`: the formatter walks
  `build/` and crashes on stale Gradle folders.
- Plural forms use ICU: `=0`, `=1`, `other`. Portuguese and Spanish need the
  same three forms.
- Do not put placeholders inside `@key` names; only the key gets metadata.
